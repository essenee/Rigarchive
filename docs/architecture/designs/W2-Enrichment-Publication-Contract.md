# W2: Enrichment and catalogue publication contract

**Status**: Approved architecture contracts, incorporating director-approved Phase A corrections on 2026-11-04. B1 pure serializers/validators are implemented; persistence/publication execution is not implemented. No migration or canonical-write authorization.

## 1. Versioned artifacts and boundaries

New contract family: `rigarchive.full_specifications_enrichment.v1`, schema `1.0.0`; review manifest `rigarchive.full_specifications_publication_manifest.v1`, schema `1.0.0`. This is separate from Candidate v2 and canonical import manifest 2.0. Existing parsers/executors must explicitly reject the new operation, not reinterpret it as VehicleDefinition import. No version number alone implies compatibility. Unknown critical fields, predicate versions or operation types fail closed. Historical readers and exact supported legacy execution semantics remain unchanged.

An enrichment draft requires:

| Field | Contract |
| --- | --- |
| `artifact_type`, `schema_version` | Exact supported family/version |
| `draft_reference` | Transient identifier, not canonical identity |
| `target` | Existing baseline UUID and local PK, complete identity snapshot; body/series binding if already established |
| `evidence_documents`, `assertion_references` | Complete document-qualified retained lineage, acquisition/extraction metadata and hashes |
| `corpus_inventory` | Bounded acquired corpus identity, coverage records and unresolved/excluded content |
| `interpretations` | Exact normalized values, transformations, provenance and reviewed applicability bindings |
| `proposed_members` | Complete proposed catalogue membership; exact existing revision references or complete proposed immutable records with proposed UUIDs |
| `coverage` | Four independent coverage reports below |
| `review` | Findings, conflict dispositions, truthful attribution/time, cross-document bindings and optional-equipment exception authorization if applicable |
| `expected_state` | Current catalogue leaf UUID/hash or explicit expected absence; dependent state/revision snapshots |

Persisted PKs/timestamps are generated only at authorized execution. Proposed immutable UUIDs can be reserved in artifacts without database writes; they are not canonical evidence or proof of publication. Receipt execution time is generated at actual execution, not copied from review. Do not invent a human reviewer/account. The published manifest freezes the exact UUID assignments being authorized.

Member records follow the domain contracts. Top-level scope is one exact VehicleDefinition. All component offerings must target it; reusable specification/description/item revisions need their own evidenced context. No broad family claim is projected to the baseline without demonstrated applicability. Catalogue references are resolved against the frozen publication set, not current latest objects. Existing member references bind UUID+hash. Proposed references bind UUID+full content/hash, validated as a complete acyclic dependency graph where required.

## 2. Complete-corpus inventory and coverage

Original bytes remain retained even if extraction cannot faithfully represent all cells, figures or footnotes. Inventory records identify document hash, page/section/table/row/cell or visual region, assertion references and disposition: `extracted`, `retained_pending_representation`, `excluded`, `unresolved`. Excluded requires policy/review reason, not omission. Extracted requires original/normalized relationship and qualifier provenance; a whole-page text blob alone is not semantic extraction of its tables. Track extraction gaps/visual reading order explicitly. Full documents may be retained with excluded accessory sections.

A corpus declaration lists acquired publications/revisions, scope and known missing expected sources. Inventory nodes partition meaningful content with parent-child links; children account for an extracted table's cells, headings and footnotes. No double-counted completion and no claim of completeness for unacquired sources. Reviewers may attest reconciliation of the scoped inventory, never unverifiable universal completeness.

Four required reports: `technical_specifications`, `transmission_offerings`, `equipment_offerings`, `compatibility`. Each contains state (`unverified`, `partial`, `complete_within_declared_scope`, `not_applicable`), declared universe/scope, evidence basis, known gaps/exclusions, reconciliation reviewer and time. Not-applicable requires support. Complete compatibility cannot be inferred from complete equipment inventory. Publication status is independent: a coherent published snapshot may be partial and may transparently preserve unresolved conflicts.

## 3. Normalization and review

Reuse SourceAssertionSet, immutable snapshots and explicit NormalizedInterpretation lineage. Persist document-qualified references including extraction identity; duplicate local IDs across documents are distinct. Retain original labels, units, methods, table associations and qualifiers. Automatic mapping must record exact rule version and method; interpretation is distinct from manufacturer assertion. Missing context, contradictions and unverifiable source joins block definitive promotion, not raw retention.

Catalogue semantic review verifies baseline association, exact member revisions, predicate representability, equipment policy and reported conflicts/coverage. Generation correspondence review is reused where applicable but does not prove body/specification correspondence or grant publication authority. Existing baseline UUID alone is not evidence that a new source applies to it. W1 reviewed cross-document associations remain preserved, not automatically reused for unrelated claims.

## 4. Zero-write planning and exact manifest

Planning reads existing state and retained bytes; writes no parents, identities, bodies, series, revisions, catalogue pointers, receipts or corrections. Authorized output artifacts use exclusive creation. Missing parents/body identities require a separate curation task. Baseline enrichment never creates or changes a VehicleDefinition.

Manifest fields: exact artifact family/version, `operation_type=specification_catalogue_publication`, target baseline snapshot, full draft hash/content binding, expected catalogue identity/leaf (or absence), exact member and dependency payloads/hashes, evidence documents/bytes/assertions, corpus/coverage, review/authorization references, planned outcome, proposed catalogue UUID/logical UUID/revision/predecessor, predicate/unit registry versions and complete content hash. Local execution IDs accompany stable UUIDs but do not replace them. Source identity is the complete evidence inventory; primary source convenience fields never truncate supporting evidence.

Authorization approves exactly this manifest after display/review; hash integrity is neither human authentication nor permission. No in-memory substituted plan, re-planning, changed member revision or implicit choice of latest content is allowed. New catalogue publication is separate from body/series parent curation and body-aware baseline import.

## 5. Serialization and hashes (all Phase A contracts)

UTF-8 JSON, sorted object keys, compact separators, ensure_ascii=False, SHA-256 over content excluding only its own `content_hash`/`manifest_hash`. Full lowercase prefix `sha256:`. Reject duplicate JSON keys, floats/nonfinite numbers in NEW structured W2 payloads, invalid UTF-8, noncanonical decimal strings, unknown keys and ambiguous local references. This does not change legacy readers or retained raw artifacts. Preserve raw/legacy numeric payloads by exact artifact hash/reference and verbatim text strings; do not embed their parsed float objects into new decimal fields, rewrite bytes, or recompute historical hashes. New normalized decimals must be derived explicitly from retained source lexemes/verified strings with transformation provenance, never silently rounded from a parsed binary float. Preserve original source Unicode exactly; do not normalize raw strings destructively. Dates ISO `YYYY-MM-DD`; timestamps canonical aware UTC ISO with `+00:00`. UUIDs lowercase hyphenated. Optional null is explicit per schema; no omission/null equivalence unless stated.

Lists with semantic order (gear sequence, source evidence order including primary evidence) retain order. Set-like lists (catalogue member UUIDs, definition revisions) are canonicalized by their declared stable key, reject duplicates and are validated in canonical order. Never reorder primary evidence implicitly. Source bytes are hashed independently without reserialization. A payload's acquisition/review timestamps are part of its content; actual execution timestamps/local generated PKs stay in receipts, not backfilled into authorized hashes.

Catalogue hash includes exact baseline UUID, predecessor, all members/hashes, evidence, coverage, review and effective scope. Member hash excludes only self-hash and database-generated PK/execution timestamps; includes stable/logical UUIDs, revision/lineage, evidence/review and all substantive content. All records pin exact dependency hashes. No self-referential catalogue hash in member content; member scope references baseline and external context, catalogue supplies membership. Reusing a member creates no cyclic hash graph.

## 6. Publication transaction and concurrency

Before execution, verify exact manifest, target UUID/PK and unchanged identity/parent chain, activity, evidence bytes/assertions, supported contract versions, body/series and correspondence bindings used by the applicability proof, all dependency revisions and expected current catalogue state. Changed parents/evidence/supersession/relevant conflicting bindings => stale. An unchanged historical pin can be inspected but does not automatically qualify as current publication when its dependency was withdrawn.

Execute one exact catalogue operation. Inside one atomic transaction, recheck expected state, insert new referenced immutable entities/revisions and catalogue membership, enforce chain uniqueness, advance any current pointer by compare-and-set, and persist a `specification_catalogue_publication` success receipt. Uniqueness of first revision and one successor prevents forks even when SQLite cannot provide row locks. Current pointer is a derived optimization; leaf/constraint state is authoritative. Failed receipt/storage means rollback all new canonical content and no success claim. Do not catch database integrity errors and continue publication inside a broken transaction.

Stale/rejected domain outcomes leave canonical content unchanged. After rolling back any attempted publication, write a durable attempt receipt in a separate transaction where infrastructure permits. Receipt failure is surfaced as infrastructure failure; do not claim universal durable audit under unavailable storage. Concurrent SQLite lock/write-upgrade errors may prevent either writer succeeding; stop and require a fresh review, no automatic retry.

Receipts capture operation/entity type, exact manifest hash, baseline UUID/identity, complete evidence/dependency hashes, proposed/result catalogue revision, review reference, operator attribution, actual timestamp, outcome and reason. Existing receipt fields/rows remain intact; future additive receipt schema must support enrichment without fabricating old vehicle-import values. Outcome vocabulary: `published`, `no_op_exact_match`, `aborted_stale_plan`, `rejected`; infrastructure failure is an exception, not success.

## 7. Idempotency, supersession and history

Publication replay is deterministic and requires current explicit authorization for this exact manifest. After manifest/evidence/version/target/dependency validation, look up the proposed revision UUID. If it exists with different content/hash/manifest binding or another baseline/chain, fail stale validation. If it exists exactly, return `no_op_exact_match` with a new atomic receipt ONLY when it is still the current non-withdrawn catalogue leaf with its exact reviewed finding unchanged, all pinned relevant authorization/dependency checks are valid, and the original successful receipt binds this exact manifest. This exact replay branch precedes expected-absence/predecessor checks: the operation’s own original success is the only permitted difference from those expectations. If the exact revision is superseded, withdrawn, or relevant state changed, abort stale; never reactivate it.

If the proposed UUID does not exist, enforce the manifest’s expected absence or exact current predecessor UUID/hash without exception, then publish atomically. A different existing revision, even with equal values, is not an exact replay. Changed review attribution/time/content changes the authorized hash and needs a new reviewed operation. An infrastructure failure or partial external artifact is not proof of original success. No automatic retry, substitution or fresh planning under old authorization.

Incremental enrichment produces a new complete snapshot with unchanged members reused by exact revision, new/revised claims added and removed members explicitly accounted for. Never mutate the predecessor or silently drop contradictory history. Withdrawal publishes a successor finding/receipt, preserves earlier snapshot/history and supplies a public historical warning; no physical deletion. No new catalogue implies that an older year's data applies to a new year.

## 9. Closed enrichment/publication wire schemas (normative)

Notation and primitive types come from Properties §7; Token is the reviewed token grammar in Domain §8. Braces enumerate every key: all required, null only where declared, unknown keys rejected. All hashes use §5 and all references bind UUID and hash together. This section replaces descriptive field shorthand with closed wire shapes. B1 validates these artifacts only; it implements no publication/curation executor.

### Shared references, scopes and evidence

`Ref = {uuid:UUID,content_hash:Hash}`. `ArtifactRef = {reference:Text,content_hash:Hash}` references immutable retained bytes, resolved under managed storage/path validation. No traversal or unauthorized absolute-path escape. `Effective = {status:Enum(established,unknown),production_start:Date|null,production_end:Date|null,order_start:Date|null,order_end:Date|null,notes:String}`. Established all-null dates means source-supported no narrower date restriction in the declared baseline scope; unknown never becomes unrestricted. Non-null pairs are ordered/inclusive. Unknown date restrictions cannot establish unconditional availability. `Scope = {market:CanonicalMarket|null,model_year_start:Integer|null,model_year_end:Integer|null,effective:Effective,notes:String}`; null means unknown, not global applicability. Catalogue target provides exact baseline scope; narrower source restrictions require predicates or unresolved findings.

`Document = {uuid:UUID,source_id:Text,raw_artifact:ArtifactRef,source_locator:Text,acquired_at:Time,acquisition_method:Text,media_type:Text,byte_size:Integer,publisher:Text,publication_kind:Text,revision_status:Enum(established,unknown),publication_revision:Text|null,publication_date:Date|null,original_filename:Text|null,native_publication_id:Text|null,source_scope:Scope,content_hash:Hash}`. byte_size >=0; established revision requires revision text, unknown requires null. raw_artifact.content_hash is original-byte hash; Document.content_hash covers acquisition identity. No copied parsed raw JSON numbers are required.

`Location = {page:Integer|null,section:Text|null,table:Text|null,row:Text|null,column:Text|null,paragraph:Text|null,bounding_box:Box|null,description:String}`; page is 1-based; at least one locator or nonempty description. `Box = {coordinate_system:Text,x:Decimal,y:Decimal,width:Decimal,height:Decimal}`; positive width/height, explicit source coordinate system. `EvidenceAssertion = {uuid:UUID,reference:EvidenceKey,attribute_key:Text,original_value_text:String,location:Location,retained_assertion_artifact:ArtifactRef,content_hash:Hash}`. `EvidenceKey` has exactly the EvidenceRef keys except `assertion_hash`; EvidenceRef.assertion_hash must equal EvidenceAssertion.content_hash. Exclude only outer content_hash while hashing EvidenceAssertion; no nested self-hash slot exists. Document reference hash equals Document.content_hash. original_value_text is exact source/transcription text; legacy structured assertions are referenced verbatim through retained_assertion_artifact, with original source value serialized text and recorded extraction method, never rewritten to satisfy W2's decimal contract. EvidenceRef extraction identity must match retained artifact metadata.

`Interpretation = {interpretation_id:Text,target_attribute_key:Text,evidence_refs:[EvidenceRef],value:Value,normalization:Normalization,applicability:Applicability,review:Review}`; nonempty evidence. Extraction references remain qualified even where local IDs repeat.

### Coverage and corpus inventory

`Coverage = {technical_specifications:CoverageRecord,transmission_offerings:CoverageRecord,equipment_offerings:CoverageRecord,compatibility:CoverageRecord}`.

`CoverageRecord = {state:Enum(unverified,partial,complete_within_declared_scope,not_applicable),declared_scope:Text,universe:[Text],evidence_refs:[EvidenceRef],gaps:[Text],exclusions:[CoverageExclusion],review:Review}`. `CoverageExclusion = {subject:Text,reason:Text,evidence_refs:[EvidenceRef]}`. Complete-within-scope requires a nonempty evidenced universe, established review and no unresolved gaps inside that universe. Explicit exclusions cannot disguise unsupported portions of the declared scope; scope must identify them. Not-applicable requires affirmative evidence and established review; unverified/partial must retain known gaps. Four fields remain independent and never derived from publication status.

`Corpus = {documents:[Ref],expected_missing_sources:[Text],nodes:[InventoryNode],review:Review}`. `InventoryNode = {node_id:Text,parent_id:Text|null,document:Ref,location:Location,disposition:Enum(extracted,retained_pending_representation,excluded,unresolved),assertion_refs:[EvidenceRef],interpretation_ids:[Text],reason:String}`. Nodes have unique IDs, existing parents of same document, no cycles/overlapping double-counted leaves. Extracted leaves resolve nonempty assertion refs and account for semantic content/qualifiers; normalization may remain unresolved, so interpretation_ids can be empty with a reason. Other dispositions require a nonempty reason; exclusions cite the policy or reviewed finding in reason. Source regions needing table/footnote/visual review cannot be marked fully extracted merely because page text exists. Corpus document refs must resolve to evidence_documents or exact retained dependencies.

### Target, expected state, dependency and snapshot

`Identity = {manufacturer_uuid:UUID,vehicle_model_uuid:UUID,generation_uuid:UUID,model_year:Integer,trim_name:String,engine_name:String,drivetrain:CanonicalDrivetrain,market:CanonicalMarket,body:BodyBinding,series:SeriesBinding}`.

`BodyBinding = {status:"legacy_unassessed"}` or `{status:"established",identity:Ref,semantic_digest:Hash,profile_id:"van",profile_version:"1.0",evidence_binding:Ref}`. Future profile versions require explicit support/equivalence review, not automatic acceptance. `SeriesBinding = {status:Enum(legacy_unassessed,not_separate)}` or `{status:"established",identity:Ref,semantic_digest:Hash,evidence_binding:Ref}`. Enrichment snapshots of Jeep714/715 remain legacy_unassessed, not guessed body or series assignments. Baseline snapshot identity fields exactly match existing canonical values.

`Target = {vehicle_definition_uuid:UUID,vehicle_definition_pk:PositiveInt,identity:Identity,slug:Text,parent_snapshot_hash:Hash}`. parent_snapshot_hash binds the exact supplied `ParentSnapshot`, not an uninspectable claim. `ParentSnapshot = {manufacturer:{uuid:UUID,pk:PositiveInt,name:Text,is_active:Boolean},vehicle_model:{uuid:UUID,pk:PositiveInt,manufacturer_uuid:UUID,name:Text,is_active:Boolean},generation:{uuid:UUID,pk:PositiveInt,vehicle_model_uuid:UUID,start_year:Integer,end_year:Integer|null,is_active:Boolean}}`. Validate FK chain, activity and year bounds. No range/slug/name changes are authorized by enrichment.

`Expected = {state:"absent"}` or `{state:"current",catalogue:Ref,logical_uuid:UUID,revision_number:PositiveInt}`. `Dependency = {kind:Enum(evidence_document,evidence_assertion,definition,transmission_description,transmission_offering,equipment_item,equipment_offering,compatibility_rule,physical_feature_mapping,body_identity,series_identity,body_binding,series_binding,generation_correspondence,unit_registry),revision:Ref,expected_leaf:Ref|null,finding:Enum(established,unresolved,withdrawn)}`. expected_leaf is required nonnull for revisioned live bindings; immutable unchained records use null. All dependencies used by the applicability proof are included; unexplained new conflicting live bindings stale the plan. New unpublished member dependencies resolve within the proposed set; existing ones bind their observed state. Whole-catalogue historical inspection remains possible even if a dependency later changes, but new publication/replay requires live preconditions. ParentSnapshot is included in the draft so the manifest reconstructs it exactly.

`Catalogue = {logical_uuid:UUID,revision_uuid:UUID,revision_number:PositiveInt,supersedes:Ref|null,target_uuid:UUID,finding:Enum(established,unresolved,withdrawn),members:[MemberReference],coverage:Coverage,corpus_hash:Hash,evidence_refs:[EvidenceRef],effective:Effective,review:Review,removals:[Removal],content_hash:Hash}`. `MemberReference = {kind:MemberKind,revision:Ref}`; unique/sorted by (kind,uuid). All dependency members are included in snapshot membership, not only displayed rows. `Removal = {member:MemberReference,reason:Text,evidence_refs:[EvidenceRef]}`. Initial revision_number 1 requires supersedes null and removals empty; successor is same logical target chain n+1 with exact predecessor. Members are the complete current state; withdrawn status is not an empty patch masquerading as supported content. Removed predecessor members require one removal record; no unaccounted omissions. Evidence and Coverage remain pinned content. No dynamic latest lookup.

### Closed member payloads

`MemberKind = Enum(definition,specification_assertion,transmission_description,transmission_offering,equipment_item,equipment_offering,compatibility_rule,physical_feature_mapping)`. A member record is `{kind:MemberKind,content:MemberContent}`. Each content hash covers all its own content except self-hash. The corresponding MemberReference uses assertion_uuid or meta.revision_uuid as appropriate.

`QualifierRule = {key:Token,value_kind:Enum(quantity,range,integer,boolean,category,text),dimensional_family:Token|null,required:Boolean,categorical_definition:Ref|null}`. Quantity/range definition or qualifier requires dimensional family; other kinds require null unless a controlled semantic rule explicitly establishes a dimensionless family. `SequenceRule = {element_kind:Enum(quantity,range,integer,boolean,category,text),contiguous_indices:Boolean}`; present only for ordered_values definitions. Sequence dimensional family applies to quantity/range elements. Definition keys are dot-separated reviewed property tokens, using the Domain token grammar. Definitions have no default unit. Category terms are nonempty only for category definitions; empty otherwise. Definition evidence may cite controlled source concepts, not a fabricated vehicle value. Transmission known statuses require nonnull supported type/count; unknown requires null.

`ItemContent = {item:Ref,quantity:PositiveInt|null,condition:Applicability,replaces:[Ref]}`. Package contents reference exact item revisions, not independently inferred optional offerings. Nonpackages have empty contents; factory package requires nonempty documented contents. Cycles and unresolved replacement targets block establishment.

`EquipmentPolicy = {brochure_document:Ref|null,brochure_listed:Boolean,manufacturer_identifies_package:Boolean,exception_authorization:ArtifactRef|null,evidence_refs:[EvidenceRef],finding:Enum(eligible,review_required,excluded),reason:Text}`. Ordinary optional/package/accessory eligibility requires applicable brochure evidence; package identity/contents supported; accessories absent from brochure always excluded. Standard facts may use other authoritative evidence; null brochure is not permission to promote optional equipment. An eligible non-brochure factory option/package requires exact reviewed exception authorization. review_required/excluded items may be retained as drafts/inventory but cannot be published as selectable established offerings. Accessories are catalogue-only and barred from rules/mappings/effects.

`OfferingOperand = {kind:Enum(transmission_offering,equipment_offering),revision:Ref}`. `RuleBody` is exactly one of:

- `{kind:Enum(requires_all,requires_any,excludes),trigger:OfferingOperand,operands:[OfferingOperand]}`; operands nonempty/unique.
- `{kind:"includes",trigger:OfferingOperand,items:[Ref]}` or `{kind:"replaces",trigger:OfferingOperand,removed_items:[Ref],added_items:[Ref]}`; nonempty item arrays.
- `{kind:"cardinality",offerings:[OfferingOperand],minimum:Integer,maximum:Integer}`; 0 <= minimum <= maximum <= array length; nonempty unique offerings.
- `{kind:"supports_combination",offerings:[OfferingOperand],scope_complete:Boolean,universe:[OfferingOperand]}`. Exact supported combination when scope_complete false: universe empty, whole selected set in scope equals offerings. When true, universe nonempty covers offerings and selected members, and cited reviewed evidence establishes a complete restriction rule set for that universe. This declaration alone does not prove completeness: its evidence and semantic review must establish it. Inclusion/replacement targets do not become automatically selected offerings.

All RuleBody operand refs belong to pinned baseline/snapshot; no accessories. Arrays are unique/sorted by (kind,uuid), item refs by uuid; all selected-set comparisons account for baseline standard assignments without claiming installed equipment. No silent prerequisite insertion or arbitrary arithmetic. General NOT remains unsupported. Cross-references are validated before predicate evaluation; unknown operators/fields/types fail closed.

### Draft and manifest

`Enrichment = {artifact_type:"rigarchive.full_specifications_enrichment.v1",schema_version:"1.0.0",draft_reference:Text,target:Target,parents:ParentSnapshot,evidence_documents:[Document],assertion_references:[EvidenceAssertion],corpus_inventory:Corpus,interpretations:[Interpretation],proposed_members:[ProposedMember],catalogue:Catalogue,expected_state:Expected,dependencies:[Dependency],unit_registry:ArtifactRef,predicate_version:"1.0",review:Review,content_hash:Hash}`.

`ProposedMember` is `{state:"existing",member:MemberReference}` or `{state:"new",member:MemberReference,payload:MemberRecord}`. Every catalogue member has exactly one matching proposed member; no extras. Hash/kind/UUID agree with payload or resolved immutable existing record. `MemberRecord = {kind:MemberKind,content:MemberContent}` means the closed variant shape above. Dependencies outside membership must be explicitly scoped evidence/registry/body/series/correspondence records, never hidden offering latest lookups. unit_registry artifact is pinned, reviewed and follows UnitRegistry below; no inferred seeds.

`PublicationManifest = {artifact_type:"rigarchive.full_specifications_publication_manifest.v1",schema_version:"1.0.0",operation_type:"specification_catalogue_publication",created_at:Time,draft:Enrichment,draft_hash:Hash,planned_outcome:"publish",replay_policy:"exact_current_only",authorization_scope:Text,manifest_hash:Hash}`. draft_hash equals draft.content_hash; full nested draft binds target, exact proposed catalogue, coverage, dependencies and expected state without duplicated mutable fields. authorization_scope describes the reviewed operation, not proof that a user authorized it. External current director authorization is required at execution; receipt records actual attribution/time. Both publish and permitted replay use this exact manifest; no-op is an execution outcome, not changed planned content.

Canonical set ordering: documents/assertions by uuid; interpretations by interpretation_id; proposed members and catalogue members by (kind,revision.uuid); dependencies by (kind,revision.uuid); inventory nodes by node_id; gaps/universe/missing-source strings lexically; exclusions by (subject,reason); removals by (kind,uuid); qualifier_rules by key. Reject duplicates at every unique key. Evidence arrays retain original primary-first order. New payload members may not introduce dependency cycles. Opaque unknown content remains retained artifact text/reference, not undeclared schema extensions. Catalogue completeness is independent from lifecycle finding at all revisions.


`UnitRegistry = {registry_version:Text,units:[UnitDefinition],review:Review,content_hash:Hash}`. `UnitDefinition = {token:Token,dimensional_family:Token,name:Text,reference_unit:Token|null,factor_numerator:Decimal,factor_denominator:Decimal,offset:Decimal}`. Unique unit tokens sorted lexically; denominator nonzero; a family root has reference_unit null, factor 1/1 and offset 0; others reference that existing family root (no cycles). Exact rational unit relationships are metadata, not permission for rating derivation. Definition/qualifier dimensional families must match registered unit family. Method/test-cycle distinctions remain separate qualifiers/definitions even where units convert. The artifact byte hash and declared canonical content hash are both checked; no unit is inferred merely from an ambiguous source abbreviation. Numeric source methods unsupported by this registry remain unresolved.


### Director clarification: categorical qualifier vocabulary (2026-11-04)

The director selected an exact categorical definition revision reference rather than a qualifier-local term list. `QualifierRule.categorical_definition` is required and nullable: category rules require a nonnull Ref to an exact pinned definition whose value_kind is category; every other qualifier kind requires null. The referenced definition's categorical_terms governs that qualifier, never the parent property's terms. Include this exact definition revision/hash in snapshot membership and dependency validation; reject missing/mismatched/noncategory references and cycles. This clarification changes only the new W2 closed contract; no legacy artifact/schema/hash is rewritten.
