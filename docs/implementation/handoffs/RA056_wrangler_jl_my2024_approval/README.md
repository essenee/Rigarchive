## Naming correction and compatibility

The authoritative name is **dynamically generated by
`reference/models.py: VehicleDefinition.__str__`**, using `engine_description` and
existing model/drivetrain display rules. It is not stored on VehicleDefinition and
is not materialized in Candidate/Plan3.1 or the native Matrix3.1 contract.

The existing method now inserts `2-Door` or `4-Door` after the marketed trim, derived
from the resolved `FactoryBodyConfiguration.door_configuration`, only for MY2024
Jeep / Wrangler / JL. It retains engine/drivetrain differentiators. No free-text
trim parsing, `Unlimited` insertion or canonical trim mutation occurs. Records
without a resolved door value retain the existing name; other manufacturers,
generations and model years retain historical naming behavior.

For example, the Sport turbo pair now displays as:

- `2024 Jeep Wrangler Sport 2-Door 2.0L I4, Turbocharged 4WD`
- `2024 Jeep Wrangler Sport 4-Door 2.0L I4, Turbocharged 4WD`

Package generation attaches each plan's exact resolved body to an unsaved
VehicleDefinition (with UUID allocation disabled) and calls that same method.
There is no duplicate formatter in the approval layer. All 31 names were checked
against the model method and their resolved body values.

All plans, candidate identities, canonical trims/slugs, Generation/Engine/body UUIDs,
Engine classifications and original evidence remain unchanged. RA-054/055 source
corrections and historical 3.0.0 behavior are preserved. No schema or naming
framework change was made.
